要点5
  • 增长逻辑从“影响力驱动”转向“流量驱动”：获客半径从社交半径变成内容分发半径。
  • 常年顾问等咨询类、文书代写、标准化诉讼被列为 AI 直接替代类业务；增量在 AI 产业链与风险链。
  • 律师侧个人 AI 使用率已接近饱和，效率提升不等于收入提升；客户带着 AI 结果来问“可靠吗、适用我吗、下一步是什么”。
  • 认知三跃迁：工具到要素、会用到会造（重构工作流而非堆 skill）、单向应用到双向（AI for law 与 law for AI）。
  • 三点建议：算清成本（直接、时间、安全）；界定目标、边界、角色；用 AI 如用人。
可直接用的方法3
  • 用 AI 先定义收益：提效、降本、提质、拓展机会、扩充能力，其中降本要体现在客户身上。
  • 在“极客”和“游客”之间找适配区：通用工具与专用工具结合，标准化与个性化结合。
  • 私有化从一个小场景、本地知识库、小模型起步，逐步扩充。

广东省人工智能产业协会法律专业委主任、《法律人AI应用场景指南》作者

Agent 时代真正的分水岭是上下文管理和核验能力；AI-native 律所既用 AI 解决法律问题，也用法律解决 AI 问题。

要点5
  • 法律结果不能像代码一样当场验证，“提高核验的可信度和效率”是下一阶段的分水岭。
  • 上下文管理三步：选对入口（工作空间 project 思维）、汇集上下文（聊天、会议记录落盘）、沉淀上下文（session 沉淀为 skill 或知识库）。
  • 长期项目第一步先把材料转成 Markdown；材料多时多开 Agent 交叉核验，最后一轮由人核。
  • 组织三层：个人上下文、团队资料 Agent 可读、客户上下文（让客户的 AI 写一份背景 md 交过来）。
  • 桌面工具不等于数据不出域；敏感材料走“本地识别、替换、留映射、云端处理、还原”。
可直接用的方法2
  • 时间线图、人物关系图、争议焦点三段提示词：保留来源编号和页码，待核单列，不加未经证实的因果，区分主张与认定。
  • 3+1+3：三个云端 Agent 分工互审，一套本地模型处理敏感材料，三套支持系统（数据库、协作、文件留存）。

打造 AI 时代的数智化律所与律师团队——从个人提效到组织价值

潘扬
10/31 14:50—16:00

植德律师事务所首席运营合伙人

个人把经验写成任务设计，团队把任务设计变成稳定交付，律所把稳定交付变成可治理、可运营的能力；AI 只是让任务更高效，而不是更简单。

要点6
  • 作业价值光谱：信息读取、整合分类、生成初稿越来越被 AI 压缩、明码标价；判断取舍、承担责任必须由人负责，也越能非标定价。
  • 同一个模型，一个团队三种结果：团队用 AI 的优势不在谁更会提问，而在有没有统一的使用方式和规则。
  • 把“帮我审合同”写成可验收的任务单：业务场景、交付物、立场、现有与缺失信息、禁止 AI 自行完成的事、律师判断的事。讲者的做法是先用免费网页模型理清任务链，导出 Markdown 任务书，再交给桌面 Agent（讲者口述）。
  • 合同审查先确认意见，再生成修订稿：分析和修改分开，中间设律师确认立场的闸门，改完对照原文复核；再把自己的修订版与 AI 版对比，反向升级 Skill（讲者口述）。
  • 上下文不是越多越好：按相关性、权威性、版本性、完整性、权限性把关，关键缺失列入待确认清单，不让模型补全交易事实。
  • 大客户开始尽调律所的信息安全与数据权限；明年 AI 治理业务将大量出现（讲者口述）。
可直接用的方法5
  • 团队协作四类规则：输入（材料齐全才开工）、判断（统一立场与风险分级）、交付（统一模板）、成本（模型与资源用量），每类指定责任角色。
  • 团队资产阶梯：模板与常用文件→清单→SOP→Skill；重复发生、流程稳定、输入输出固定、多人共用四个信号越明确，越值得封装成 Skill。
  • 团队评测集：合格样本、错误样本、高风险边界案例、人工复核记录、版本对比；每次换流程、模型或 Skill，都用同一批脱敏真实样本打分。
  • 五维验收表：法律与来源、事实与材料、客户与商业、文本与一致、交付与责任，逐项区分“AI 可辅助”和“律师必须确认”。
  • 第一轮用强模型把材料抽成“控制表”，后续复用不再重读；一主两辅分开使用不同 Agent 实例，防止记忆污染（讲者口述）。

大模型技术概述和主流模型能力介绍

丁文婧
11/01 09:30—11:00

阿里云AI解决方案架构师

模型本身是无状态的概率模型，智能体的能力来自外层有状态的编排；用好它靠说清需求、可照做的 SOP、结构清晰的文件夹和合适的模型，而不是堆技能、用最贵的模型。

要点5
  • 一个 AI 产品背后是多个模型，没有全能冠军：先拆任务，再按任务选模型，最后复核。
  • 智能体与网页聊天的三点区别：上下文（文件夹内资料可见）、工作单位（一案一项目一文件夹）、产出（交付物而非一段话）。
  • 知识库不一定做 RAG：结构清晰、每层有 README 的文件夹，配合 Agent 逐层查找，效果不一定差。
  • 积分消耗快，常因 skill 全开、记忆冗长；规则明确的任务让模型写成代码执行，普通模型能做的不用最贵的模型。
  • 微调的难点在数据质量：卷宗多不等于语料好，相互矛盾的数据训不出好模型。
可直接用的方法3
  • SOP 检验：新来的实习生拿到能否照做；写清触发条件、中间步骤和判断。
  • 防幻觉：要出处、要原文、打开链接核对；给材料让它基于材料作答；人一定要看。
  • 现成 skill 只作参考，让模型按自己的流程和格式在上面改，迭代出自己的。

工作流 AI Agent 高阶实操（上）

揽盛
11/01 11:10—12:00

阿里巴巴集团ATH事业群千问办公事业部AI产品专家

各家办公 Agent 在功能上已拉不开差距，要让 work agent 真正干活，靠的是划清工作区、写好规则文件、维护好上下文和记忆；上午讲的是“看得见”这一部分，实操放到下午。

要点4
  • Agent 由四部分组成：大脑（LLM）、手脚（工具/MCP）、工作方法（skill）、视野（context）。生产级 Agent 是 ReAct、先规划再执行、Reflection 三种循环的组合，例如合同审查的“通读、切片、判官复核”三明治结构。
  • 工作区决定 Agent 能读写什么、加载哪套规则、产物放在哪里，同时是物理上的安全边界。只有桌面端能碰到本机文件；沙盒里的路径不等于真实文件夹。
  • 每个案子配一份 AGENTS.md，写明背景、红线、交付格式，目录固定为输入材料、中间产物、交付物、归档。动手前先让 Agent 报一遍目录。
  • 模型本身不记事，长对话每一轮都要把历史重发一遍、重新付费。长期记忆和 USER.md 等基础文件要定期人工复查，改动交给 Agent 去做。
可直接用的方法2
  • 目录卫生五条：一事一目录；文件名带版本号和时间；成品写回宿主工作区；先报目录再动手；每个案子的固定规矩写进本目录的 AGENTS.md。
  • 用语音口述案情和要求，让 Agent 自己整理成 AGENTS.md；结果很好或很差时，单独说一句“写进长期记忆”。

让 Agent 干得了活，靠的是管好上下文成本、把执行链路写死在 skill 和脚本里、用子代理分工、用连接器取数；连接器只解决数据来源，推理是否守边界仍要核验。本节讲完“干得了”，“管得住”未讲完，资料包实操未开始。

要点5
  • 每轮对话都把全部历史重发一遍；提示词缓存只在前文不变时生效，改前文、中途换模型、隔太久再续都会让缓存失效。一次说清、先大纲后全文、拆大任务、复用产物，都是在省 token。
  • 选模型问三件事：失败代价高不高、产物是否对外、链路长不长。日常用标准档，推理重的活（如从银行流水推资金去向）再升档。
  • 生产级法律 skill 除版本、适用场景、步骤、边界、验证外，还要有结构化字段（审查立场、合同类型、地区行业）、本地规则（地区、法院、法官偏好）和与相邻 skill 的边界；不稳定的操作（如批注）写成脚本固定执行。
  • 套件（plugin）是 N 个 skill 加 MCP，相当于一个岗位，能替代该岗位约 80% 的工作才值得做；子代理上下文隔离、可并行，主代理像项目经理。
  • 管控分三层：沙盒和白名单、审批策略、提示词约束，最后一层基本不起作用。
可直接用的方法3
  • 写 skill 时把“要求”改成“必须输出的字段”，示例材料与真实材料同量级，迭代时把真实产出和差的案例一起交给它改。
  • 大任务拆成多个会话分别出产物，再开一个会话贴入前几个会话的 ID 汇总；改版时旧版存 1.0、新版 2.0。
  • 交付前让 Agent 按要点清单自查，再新开会话、换模型复核一遍。

AI 程序开发入门

雷宇
11/01 15:20—16:50

深圳市人工智能学会法律专委会秘书长

coding agent 已能独立写代码、运行和修改，律师做工具的门槛从会不会编程变成能否讲清需求、能否验收结果，而这正是律师的专业强项。

要点5
  • 律师与 AI 分工：律师定问题、业务规则、对错标准和最终验收；AI 负责技术方案、代码、数据存储、测试和调试。业务规则必须由人定。
  • 从需求到落地八步：准备环境、需求对齐、写 spec、看原型、开发测试、验收、修 bug、迭代，写代码只占很小一段。
  • spec 要写明“这一版不做什么”；需求对齐时 AI 给出的推荐答案要逐条核对，不能顺手回“是”。
  • 设计原则：AI 只做判断，后续动作由程序按规则执行，拿不准的单列待人工核实，原件始终不动。
  • 验收靠测试材料、标准答案、及格线、逐项清单和回归重跑，改原件、丢材料、编造回答一票否决。
可直接用的方法3
  • 报 bug 四要素：做了什么、希望看到什么、实际看到什么、是否每次如此；再区分实现错误、需求偏差、规则缺口，规则缺口回去改 spec。
  • 用 Context7 查最新官方文档，提示词加一句“先查文档再写代码”；需求对齐、写 spec、看原型、修 bug 各用一个 skill，开发用目标模式。
  • 鲁棒性测试：故意放入加密、空文件、压缩包、重复文件，检查是否单列、不影响其他材料、不改原件。

金句

1 / 12

当日主线

  1. 模型无状态，功夫在模型之外：四讲都落在同一点：模型和产品之间的差距在缩小，AI 产出的质量和成本取决于给它的上下文、文件夹结构、规则文件和技能。
  2. 以项目为单位工作：一案一文件夹、每层放 README 或 AGENTS.md，工作区既是 AI 的办公桌，也是安全边界；动手前先让它报一遍目录。
  3. 把方法写成文件：SOP、AGENTS.md、skill、记忆，都是把律师的工作方法变成 AI 可读、可复用的资产；检验标准是“新来的实习生能否照做”。
  4. 用得省也是能力：按任务选模型，确定性规则交给代码，关掉不用的技能，定期清理过时记忆。
  5. 工具取数，人管推理：连接器和数据库解决材料从哪来，结论对不对、守不守边界仍要核验；不稳定的操作写成脚本固定执行，交付前新开会话或换模型复核。
  6. 律师做工具靠需求与验收：AI 能写代码、能干活，但术语、规则、边界和验收标准必须由律师写清；判断交给 AI，执行和计算交给规则与程序，改原件、丢材料、编造一票否决。

用 Qoder 从零做出本地运行的“案卷整理助手”：拖入材料 → 读出文字 → 按内容分到我方、对方、法院各类目录并生成材料卡 → 针对本案提问，回答必须注明出处，材料里没有就说未找到。技术约定：Python 3.11.15 + AgentScope 2.0.11，模型 qwen3.8-flash（阿里云百炼），也可改用 DeepSeek，Key 放 .env，第一版不做 OCR。

## 整理规则
- 案卷目录（文件夹名不加编号）：
  待整理
  我方材料：身份与授权、证据材料、诉讼文书、律师工作成果、沟通记录、其他
  对方材料：身份与授权、证据材料、诉讼文书、其他
  法院材料：程序通知、裁判文书、其他
- 是谁的材料：法院制作的，是法院材料；我方当事人或我方律师制作、提交、持有的，是我方材料；
  对方当事人或对方律师提交的，是对方材料。当事人向法院提交的申请（如财产保全申请书）不是法院材料。
- 放哪一类：起诉状、答辩状、各种申请书放"诉讼文书"；受理通知书、传票放"程序通知"；
  判决书、裁定书、调解书放"裁判文书"；合同、转账记录、作为证据的聊天记录放"证据材料"；
  身份证明、授权委托书放"身份与授权"；律师函、证据目录、庭审提纲放"律师工作成果"；
  和当事人的沟通纪要放"沟通记录"。
- 拿不准的（AI 把握程度低，或者看不出是谁的）一律放"待整理"并写明原因，不要硬塞。
- 原件只复制、不改动；第一版不重命名，重名时在后面加 (2)、(3)。

## 案件对话的规则
- 只根据本案已经读出文字的材料回答，每个回答都注明出自哪份材料。
- 材料里没有的，直接说"材料中未找到"，不能猜；涉及还没读出文字的材料，要点名提醒。
- 第一版不做：起草文书、检索法规和案例、跨案件提问、预测输赢。
